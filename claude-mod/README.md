# The bundled Claude mods

Two Claude Code mods (plugins whose hooks module draws inside Claude Code):

- `inline-images/`: the PNGs a Claude session sends (SendUserFile) or reads (Read) are drawn as framed pictures in the terminal, with Open, Save to Downloads, and Copy path. Its look and some of its speed-ups come from show-your-work (MIT; `inline-images/THIRD_PARTY_NOTICES.md`). A read picture is drawn from the PNG Claude got, when it got one under the terminal's 2 MiB limit: that's what it saw, and it outlives a deleted temp file. A large picture Claude Code shrank (often to a JPEG) is drawn from its file instead, when that's a PNG still there; anything else isn't drawn. Reads Claude Code folds into a `ToolGroup` line ("Read 2 files, ran a shell command") are drawn under that line, each file once as its newest read found it, at most four (the newest), with a line saying how many more; a Read outside a group is drawn from its `ToolUse` row, which carries both its input and its output (its `ToolResult` row has no input).
- `quiet-tools/`: `/quiet` folds each tool's output into one dim line under its header, and back again, redrawing every row at once; `/quiet on` and `/quiet off` set it. It hooks `ui.render` for every `ToolResult` row and folds only the tools in `FOLD` (in its module) and MCP tools; every other tool's row, a call that failed, and a row shown in full (Ctrl+O) are Claude Code's own drawing. Whether it's on is a `$.state` value (so a change redraws every row that read it) saved in `$.store`, which Claude Code keeps in `~/.claude/plugins/store/`. Rows already drawn change only in Claude Code's fullscreen rendering.

**How they ship.** The build bundles every mod folder here into `main.js` as text (`esbuild.config.mjs`, the `claude-mod-files` module), without the API types copied in to check them or their tsconfigs. On load the plugin writes them into its own folder, `<vault>/.obsidian/plugins/agent-manager/claude-mod/<mod>/`, only when they differ (`src/plugin/claude-mod.ts`), and every Claude start and resume gets one `--plugin-dir` per mod whose setting is on (`src/sessions/controller.ts`): inline-images while "Show pictures Claude sends or reads" (under Advanced & experimental) and "Pictures in the terminal" are on, quiet-tools while "Fold tool output" is (both on by default). The strip's Quiet button sends `/quiet`, and shows only on a session started with quiet-tools; its icon follows the state the mod reports in a file the plugin names per tab (`AGENT_MANAGER_QUIET_STATE`, in `<plugin folder>/quiet-state/`, deleted when the tab closes and emptied at each load). Nothing is downloaded, and the plugin writes nothing to `~/.claude`.

**By hand.** `.claude-plugin/marketplace.json` makes this folder a marketplace (`agent-manager-mods`) for installing either mod at user scope. With a copy installed that way and the bundled one together, inline-images draws each picture once: the outer copy's hook sees the frames the inner one drew (`hasFrames`) and adds none. quiet-tools registers `/quiet` once, and only one copy's hook answers it. Each copy has its own store (Claude Code keys it by where the mod came from) but they share one state, which is why a 2026-11-02 test with both loaded started the wrong way round; one copy at a time is still the supported setup. quiet-tools takes the saved choice only when the session's state was never written, so with two copies the first to start sets it; both write the strip's state file, the same one, since its path is in the process's environment.

**Checking them.** `claude plugin validate claude-mod/<mod>`. To type-check, copy the Claude Code build's API types to `<mod>/.claude-plugin/types/claude-code/index.d.ts` (not tracked: Claude Code's `plugin-authoring` skill names the file) and run `npx tsc -p claude-mod/<mod>`.
