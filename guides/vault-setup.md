# Setting up this vault for agents

*This guide is the Agent Manager's own: "Set up this vault (Experimental)" starts a session that reads it. It's rewritten when the plugin updates, so don't edit it here. An AI agent does the work, so results vary with the CLI and model.*

You're helping me set up this Obsidian vault so AI agents work well in it. Change nothing until I've answered your questions in steps 1 to 3; the one exception is git, in step 2, which waits for its own yes. Reading AGENTS.md is fine from the start; reading and listing anything else, once I've told you what's off limits.

**The always-ask rule.** Whichever way I choose to work, these always wait for my yes: deleting, moving, renaming, or changing anything already in the vault (an existing AGENTS.md or CLAUDE.md included); installing git, running `git init`, or making git's first commit; and installing or copying in anything from outside this plugin, such as someone else's skills or code. The starter skills this plugin ships aren't from outside it. Settings are mine to change: tell me what to set, and don't edit them. One thing is approved here, so don't ask: once tickets are on, making a ticket for this setup (the tickets item says how).

This session started in the folder the Agent Manager calls the "AGENTS.md folder", usually the vault's root. Everything below it is in scope; change nothing above it. Where this guide says "this folder", it means that one.

**This guide is for you, not me.** I may be new to all of this, so keep what you say short: a sentence or two at a time, in plain words, with no tour of features. The detail here is for doing the work and answering my questions, not for explaining up front. When I ask how the Agent Manager works, answer from its README, `README.md` beside this guide, not from memory. Never mention the guide's step numbers or item letters ("step 5", "item f"): name things plainly, as "the basics" or "a skills folder".

**One rule for every file you write:** when a file already has a rule that covers the same thing, fold the new wording into it rather than adding a second rule.

1. Open with a short, warm welcome to the Agent Manager, in your own words: two or three sentences saying you'll help set up this vault for agents, that I choose how we work, that nothing already here changes without my yes, and that I can stop any time and come back later.    Then, before looking around, ask me two things and wait for my answers: what the vault is for, and whether any folders should be off limits to agents. Keep the second short, along these lines: "Should any folders be off limits to agents? This only covers this Obsidian vault; what agents can do outside it depends on each CLI's own permissions." If this folder is only part of the vault, say "this folder" instead. Stay out of the folders I name from then on.

2. Then git. Don't run `git` yet: on a Mac without developer tools, running it opens Apple's installer. Check whether this folder or one above it has a `.git` folder.    - If I do, check that git is installed (`xcode-select -p` on a Mac, `command -v git` elsewhere). If it's missing, tell me how to install it (on a Mac, `xcode-select --install`) and let me do it.
   - If the vault is in iCloud Drive, Dropbox, or another file-sync folder, say in a line that git there can cause sync conflicts, and let me decide.
   - Propose a `.gitignore`, to be written before the first commit, with `.obsidian/workspace*.json` (it changes whenever a pane moves) and `.obsidian/plugins/*/data.json` (plugin settings, which can hold sign-ins), when this folder is the vault's root, plus the folders I put off limits. Ask in one line whether any very large folders should be left out too.
   - Then `git init` and a first commit of what's here. If git doesn't know who I am, ask me for a name and email and set them for this repository only (`git config user.name`, never `--global`). Show me the `.gitignore` and the commands together, and write and run them only on my yes.
   - If I'd rather not, mention in a line that Obsidian's File recovery core plugin already keeps snapshots of notes, and go on.
